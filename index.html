Subtitle Timer

View on GitHub

A desktop tool that watches a video for you and works out exactly when each burned-in subtitle appears and disappears, producing a ready-to-edit .srt file. It replaces hours of frame-by-frame scrubbing with a stopwatch.

Instead of OCR or speech recognition, it uses a small CNN I trained from scratch to classify every sampled frame as no subtitle, normal style, or special style. The user positions up to three independently-toggled crop boxes on a preview — two for normal-style subtitles and one for a special stacked style — and a single pass classifies and times all of them together, then writes the result out as a standard subtitle file. Trained in PyTorch, exported to ONNX, and run through OpenCV's DNN module so the packaged app has no PyTorch dependency.

  • End-to-end ML Dataset creation tooling, training with augmentation, ONNX export, and cross-framework validation — checking PyTorch and OpenCV DNN agree on every frame before shipping.
  • The hard case Two subtitles back-to-back with zero gap look like one long subtitle to a presence detector. A two-tier glyph mask — bright pixels near saturated color — catches the text changing even on low-saturation text, while ignoring noisy outlines that used to trigger false splits.
  • Debugging a model Diagnosed a colour-invariance failure in the trained classifier and fixed it with targeted hue-rotation augmentation rather than collecting and labelling new data.
  • Automatic timing corrections Two learned quirks are corrected automatically after detection: the special style's banner lags its true on-screen end by a fixed delay, and any block boundary landing on a frame-rounding edge case is nudged to stay frame-accurate — even where regions overlap and boundaries must move together.
  • Real desktop app Live video scrubbing, draggable and resizable overlays synced with numeric fields and on/off toggles per region, auto-detection of the newest trained model, background-threaded processing with cancellation so the UI never freezes, and a standalone .exe for non-technical users.

UNO Online

Personal project · Full-stack, real-time

2026

  • Node.js
  • Raw WebSocket protocol
  • Docker
  • Hugging Face Spaces
Play live View on GitHub

A full multiplayer UNO game for up to 15 players per room, playable in any browser with nothing to install — built entirely on Node.js's built-in http module and deployed as a Docker container on Hugging Face Spaces.

One player creates a room and gets a 6-letter code; everyone else joins with it and the host starts the game once at least two people are seated. The full rule set is implemented — number cards, Skip, Reverse, Draw Two, Wild and Wild Draw Four, draw stacking, UNO callouts with a catch window — plus a rematch flow with a running win scoreboard.

  • Zero dependencies package.json lists no runtime dependencies at all — the WebSocket handshake, frame parsing, and keepalive ping/pong are hand-implemented over Node's raw http module instead of pulling in a library.
  • Reconnect-proof state Each player is tracked by a stable public id and a secret token, kept separate from their transient socket connection, so refreshing the page, losing Wi-Fi, or locking the phone reclaims the same seat and hand instead of ending the game.
  • Graceful disconnect handling A disconnected player's turn auto-passes after 20 seconds instead of stalling the table for everyone else; a disconnected host gets a 60-second grace period before the room closes, so one dropped connection doesn't end the game.
  • Shippable anywhere Runs with a single node server.js locally, or as a Docker image behind Hugging Face Spaces' proxy — including the periodic pings needed to keep the proxy from dropping idle sockets.
